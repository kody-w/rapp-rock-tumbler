The loop

Seven steps. Each exists because a specific bug got past everything else.

  1. Serve over HTTPNever file:// — OPFS, workers and ES modules all fail silently there and give you false failures.
  2. Launch a real browserWith GPU flags. Without them WebGL and WebGPU quietly fall back and you find bugs that only exist in your harness.
  3. Capture every errorThen identify each one before dismissing it. A bare test server's own /favicon.ico 404 will masquerade as an app defect.
  4. Drive the appClick the start gate. Press the keys. Open the tab nobody opens. Run the app's own self-test if it ships one.
  5. Measure from outside the pageScreenshot to PNG and compute over the pixels yourself. Page-side code can tell you whatever it likes; a PNG cannot.
  6. Return a number, not an adjective"The road is green" gets argued with. "Road RGB [90,102,70] at 0.316 saturation" gets fixed.
  7. Loop, then re-sweepFixes break other things. Re-run the whole pass after every change.

The single most useful result

Of the ten applications, exactly one shipped correct on the first attempt with zero correction loops. It was also the only one whose prompt contained an objective, self-administered fail condition.

The WebGPU path tracer was told: run the white furnace test — put the camera inside a uniformly emitting sphere with albedo 1.0; every pixel must return exactly the emitter's radiance; if energy error exceeds 1%, your integrator is wrong. It came back at 0.49% and it was telling the truth.

The other nine were graded on "make it AAA quality." All nine reported success while broken — not maliciously, but because a subjective bar can always be argued into.

If you can name the measurement, put it in the prompt, not in the review.

Run it yourself

git clone https://github.com/kody-w/rapp-rock-tumbler
cd rapp-rock-tumbler/harness
npm install
npx playwright install chromium

node tumble.mjs /path/to/your/site index.html --seconds 9
